# 포트폴리오 사진 관리

분류 → 프로젝트 폴더 → 리모델링 구역 → 사진 구조로 관리합니다. 프로젝트 폴더명과 관계없이 해당 폴더의 `INFORMATION.md`에 표시 정보를 작성합니다. 리모델링 구역은 하위 폴더명으로 표시합니다.

```text
portfolio/
  주거공간/
    송파구 꿈에그린/
      INFORMATION.md
      거실 및 복도 사진/
        KakaoTalk_20261008_165020451.jpg
        KakaoTalk_20261008_165020451_01.jpg
      주방/
        주방 사진.jpg
      현관사진/
        현관 사진.jpg
  상업공간/
    shop-001/
      INFORMATION.md
      홀/
        매장 전경.jpg
      카운터/
        IMG_0001.jpg
```

- 최상위 분류는 `주거공간`, `상업공간` 두 가지입니다.
- 그 아래 프로젝트 폴더명은 자유롭게 정합니다. 폴더명은 URL·파일 경로에만 사용하고, 화면 제목·지역·주소·설명은 `INFORMATION.md`에서 가져옵니다. 폴더명을 바꾸면 페이지 주소도 바뀌므로, 표시 이름만 바꾸려면 정보 파일을 수정하세요.
- 프로젝트 내부 폴더는 리모델링 구역입니다. 구역 폴더 안의 더 깊은 하위 폴더도 같은 구역으로 묶어 순회합니다.
- 사진 파일명에는 우선순위가 없습니다. 숫자, 한글, 카카오톡 원본 파일명 등을 그대로 사용할 수 있습니다. `1.jpg`는 필요하지 않으며, `1.jpg`와 `01.jpg`도 서로 다른 사진으로 표시합니다.
- 지원 확장자는 JPG, JPEG, PNG, WebP, AVIF이며 대소문자를 구분하지 않습니다.
- 화면 표시가 매번 달라지지 않도록 구역·파일 이름순으로 정렬합니다. 번호에 따른 대표·상세 구분은 없습니다. 화면의 사진 번호는 확대 보기 위치 안내입니다.
- 목록은 최대 3장의 구역 미리보기를 같은 크기로 나란히 보여줍니다. 상세는 모든 구역과 사진을 표시하며 구역 바로가기와 확대 보기(이전·다음, 방향키, Escape)를 제공합니다.
- 사진이 없는 프로젝트·구역과 점(`.`)으로 시작하는 폴더·파일은 표시하지 않습니다. 같은 파일명을 서로 다른 구역에서 사용해도 됩니다.
- 기존 구조의 프로젝트 바로 아래 사진은 호환성을 위해 `공간 사진` 구역으로 표시합니다. 구역별 탐색을 위해 실제 구역 폴더로 옮기는 것을 권장합니다.

## 프로젝트 정보 작성

업데이트 시 각 프로젝트 폴더에 `INFORMATION.md`가 없으면 [기본 양식](INFORMATION.template.md)을 자동 생성합니다. 사진이 없는 새 프로젝트도 양식을 생성하며, 기존에 작성한 정보는 덮어쓰지 않습니다. 새 폴더에 기본 양식을 직접 복사하고 파일명을 `INFORMATION.md`로 바꾸어도 됩니다.

```markdown
# 포트폴리오 정보

## 1. 아파트명과 지역
아파트명: 꿈에그린
지역: 송파구

## 2. 주소
공개할 주소를 입력하세요.

## 3. 포트폴리오에 대한 추가적인 설명
리모델링의 의도와 공간의 특징을 입력하세요.

빈 줄로 구분하여 여러 문단을 작성할 수 있습니다.
```

상업공간은 `아파트명:` 항목에 상가·매장명을 입력해도 됩니다. 항목 이름을 `공간명:` 또는 `상가명:`으로 바꾸어도 인식합니다. 번호가 없는 `## 주소` 같은 제목도 지원합니다.

목록에는 이름·지역·설명 첫 문단 요약이, 상세에는 이름·지역·주소·설명 전체가 표시됩니다. 주소·설명이 비어 있으면 해당 항목은 숨깁니다. 아파트명·공간명을 작성하지 않으면 `주거공간 프로젝트` 또는 `상업공간 프로젝트`라는 기본 제목을 표시합니다. 내부 폴더명은 제목으로 노출하지 않습니다.

설명은 일반 텍스트로 표시하며 줄바꿈과 문단 구분을 유지합니다. HTML 주석(`<!-- ... -->`)은 작성 안내로 취급하여 화면에 표시하지 않습니다. 일반 HTML·스크립트 문구는 텍스트로 표시합니다.

## 자동 업데이트

**한 번에 업데이트·GitHub 배포:** 프로젝트 최상위의 `publish-portfolio.cmd`를 실행합니다. 생성·검증, 현재 수정 사항 전체의 커밋·push, GitHub Pages 배포와 실제 사이트 최신 버전 확인까지 진행합니다. 필요한 GitHub 로그인도 같은 실행 창에서 안내합니다. 터미널에서는 `node scripts/publish.mjs`를 실행하며, 자세한 옵션은 프로젝트 README를 참고하세요.

**GitHub Pages:** 폴더·사진·`INFORMATION.md`를 추가·수정·이동·삭제한 뒤 `main`에 업로드하면 기존 GitHub Actions가 폴더를 순회하여 목록과 상세 페이지를 생성하고 배포합니다. 최초 Pages 설정은 프로젝트 최상위의 `GITHUB_PAGES.md`를 참고하세요.

**로컬 미리보기:** 프로젝트 최상위의 `preview-portfolio.cmd`를 실행하거나 `node scripts/preview.mjs`를 실행합니다. 표시되는 주소를 열면 됩니다. 실행 창이 열려 있는 동안 약 1초마다 사진과 정보 변경을 확인하여 HTML을 자동 갱신합니다. 변경된 화면은 브라우저를 새로고침해서 확인합니다. 생성 스크립트 변경을 반영하려면 실행 중인 미리보기는 한 번 재시작합니다. 종료는 Ctrl+C입니다.

**한 번 업데이트:** `update-portfolio.cmd` 또는 `node scripts/build.mjs`를 실행합니다. 생성된 `portfolio.html`과 각 프로젝트의 `index.html`을 직접 열 수도 있습니다.

사진을 모두 제거한 프로젝트에서는 자동 생성한 상세 HTML도 정리합니다. 직접 만든 기존 `index.html`은 덮어쓰지 않고 오류로 안내합니다. 비어 있는 이미지 파일 등 오류가 있으면 기존 페이지를 유지하며, 로컬 자동 감지 중에는 오류를 고친 후 다시 갱신됩니다.

생성된 HTML을 직접 수정하기보다 폴더와 사진을 관리하세요. 브라우저는 배포된 정적 HTML을 표시하므로 로컬 폴더의 변경만으로 이미 배포된 사이트가 바뀌지는 않습니다. 변경 파일을 저장소에 업로드해야 합니다.

`INFORMATION.md`의 표시 정보는 HTML에 반영됩니다. 원본 정보 파일·기본 양식·README·`project.json`은 사이트 배포 파일에 포함하지 않습니다. 공개 GitHub 저장소에 올린 원본 파일은 GitHub에서 공개됩니다.
