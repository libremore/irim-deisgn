# 포트폴리오 사진 관리

`주거공간` 또는 `상업공간` 아래에 포트폴리오 하나당 폴더 하나를 만듭니다. 프로젝트 폴더명 전체가 지역 및 아파트명(상업공간은 상가·매장명)이자 사이트의 제목이 됩니다.

```text
portfolio/
  주거공간/
    지역명 아파트명/
      1.jpg
      2.jpg
      3.jpg
      10.jpg
  상업공간/
    지역명 상가명/
      1.jpg
      2.jpg
      3.jpg
```

- `1`번은 목록에 표시되는 대표 사진이며, 상세 페이지에서도 가장 먼저 표시됩니다.
- `2`번부터는 서브 및 디테일 사진입니다. `2, 3, 10`처럼 숫자 순서로 표시합니다.
- 파일명은 숫자만 사용합니다. `01.jpg`, `02.jpg` 같은 자리 맞춤도 지원합니다.
- 확장자는 JPG, JPEG, PNG, WebP, AVIF를 지원하며 대소문자를 구분하지 않습니다.
- 번호가 연속하지 않아도 됩니다. 다만 `1`번은 반드시 있어야 하며 같은 번호의 이미지는 하나만 있어야 합니다.
- 이미지가 없는 폴더는 목록에 표시하지 않습니다. 예시 폴더에는 안내 문서만 들어 있습니다.
- 상세 페이지의 사진을 선택하면 원본 이미지를 새 탭에서 볼 수 있습니다.

## 업데이트

1. `portfolio/주거공간` 또는 `portfolio/상업공간` 안에 지역 및 프로젝트명으로 폴더를 만듭니다.
2. 대표 사진을 `1.jpg`, 나머지를 `2.jpg`, `3.jpg` 등으로 저장합니다.
3. 프로젝트 최상위의 `update-portfolio.cmd`를 실행하거나 `node scripts/build.mjs`를 실행합니다.

포트폴리오 목록과 각 폴더의 `index.html` 상세 페이지가 생성됩니다. 생성된 상세 HTML을 직접 수정하기보다 사진과 폴더명을 변경한 뒤 업데이트하세요.

새 폴더를 추가하거나 기존 폴더 이름·사진을 바꾼 후에도 업데이트가 필요합니다. 삭제하려면 해당 폴더를 제거한 뒤 업데이트합니다. 모든 사진을 제거한 폴더에서는 자동 생성된 상세 HTML도 정리합니다. 직접 만든 기존 `index.html`은 덮어쓰지 않고 오류로 안내합니다.

## 분류 및 폴더 변경

분류는 상위 폴더에서 자동으로 결정됩니다. `project.json`은 필요 없으며, 기존 파일이 있어도 분류에 사용하지 않습니다. 같은 프로젝트명을 두 분류에 각각 사용해도 별도 항목으로 표시합니다.

기존 `portfolio/프로젝트명/` 구조의 폴더는 `portfolio/주거공간/프로젝트명/` 또는 `portfolio/상업공간/프로젝트명/`으로 옮긴 뒤 업데이트합니다. `portfolio` 바로 아래의 프로젝트 폴더나 다른 분류 폴더는 읽지 않습니다. 분류를 변경할 때는 해당 프로젝트 폴더 전체를 다른 분류 폴더로 옮기고 업데이트하세요.

## GitHub Pages

GitHub Actions 배포 설정을 완료하면 `main`에 사진을 추가·수정·삭제하는 것만으로 목록과 상세 HTML이 자동 생성되어 배포됩니다. 로컬 확인에는 기존 `update-portfolio.cmd`를 사용합니다. 방문자의 브라우저가 폴더를 직접 검색하는 구조가 아니라, 배포 시 생성된 정적 HTML을 표시합니다.

최초 설정은 프로젝트 최상위의 `GITHUB_PAGES.md`를 참고하세요. 프로젝트 README와 `project.json` 같은 관리 파일은 사이트 배포 파일에서 제외되지만, 공개 GitHub 저장소에 올린 원본 파일은 누구나 볼 수 있습니다.
